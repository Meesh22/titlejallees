# جليس | مجلس الأعضاء

المشروع المساند لموقع جليس — واجهة مستقلة تعرض **جميع أعضاء النادي** في مربّعات (شبكة)،
وعند النقر على أي عضو تفتح صفحته الخاصة بـ **الاقتباسات والمقالات والملخصات**.

> الهوية كاملة من جليس: الشعار، الأخضر `#1E3A2B`، الذهبي `#C59B63`،
> الخشب `#8C532D`، الطين `#A3503B`، خطّا **IBM Plex Sans Arabic** و **Amiri**، RTL.

## مستقل تماماً — لا يعرض الموقع الأساسي

- **كل أصوله محلية** داخل `jalees-members/` (الشعارات في `assets/`) — لا يعتمد على أي ملف خارج المجلد.
- **عامل خدمة مستقل** (`sw.js`) نطاقه محصور في `/jalees-members/` فقط، ولا يسجّل نفسه على الأصل.
- عند **انقطاع الشبكة** يعود إلى صفحة المجلس نفسه، **ولا يعرض الموقع الأساسي أبداً**.
- لا يوجد أي رابط نحو الموقع الأصل داخل واجهات المشروع.

## تقسيم الواجهة لـ ٧٠ عضواً

العدد ٧٠ له قواسم نظيفة، لذا بُنيت الشبكة بحيث يكون **كل عدد أعمدة قاسماً لـ ٧٠**،
فلا يبقى عضو وحيداً في آخر صف على أي شاشة:

| عرض الشاشة | الأعمدة | الصفوف | الناتج |
|-------------|:-------:|:-------:|:------:|
| أقل من 700px | ٢ | ٣٥ | ٧٠ |
| 700px وأكثر | ٥ | ١٤ | ٧٠ |
| 1050px وأكثر | ٧ | ١٠ | ٧٠ |
| 1400px وأكثر | ١٠ | ٧ | ٧٠ |

إضافة إلى:

- **بحث فوري** بالاسم مع تجاهل فروق الهمزات والمسافات، دون شريط حروف إضافي.
- **رقم مقعد ثابت** لكل عضو (١ … ٧٠) يظهر في زاوية المربّع.
- **مربّعات متساوية** (aspect-ratio: 1) تتناسب أحجام محتواها تلقائياً مع كثافة الأعمدة.

> لائحة الأعضاء الرسمية في `data/members.js` تضم **٧٠ عضواً** فقط،
> مطابقة حرفياً لقائمة الأعضاء المعتمدة. **لا يُضاف أي اسم من خارجها.**

## بنية الملفات

```text
jalees-members/
├── index.html       # الواجهة الرئيسية — شبكة الأعضاء
├── member.html      # صفحة العضو — اقتباسات/مقالات/ملخصات
├── design.css       # تصميم الواجهة التحريري الجديد (نفس هوية جليس)
├── script.js        # عرض الأعضاء والبحث + تسجيل عامل الخدمة
├── sw.js            # عامل خدمة مستقل (لا يعرض الموقع الأساسي)
├── manifest.json    # تعريف PWA خاص بالمشروع المساند
├── assets/          # الشعارات المحلية
│   ├── logo-icon.png
│   ├── logo-light.png
│   └── logo.png
├── data/
│   └── members.js   # بيانات الأعضاء ومحتواهم (هنا تُعبّئ المحتوى)
└── README.md
```

## إضافة عضو جديد

أضف اسماً إلى مصفوفة `ROSTER` في `data/members.js`:

```js
const ROSTER = [
  'إبراهيم الشويهي',
  'أحمد بن صالح التويجري',
  // أضف الاسم الجديد هنا…
];
```

## تعبئة محتوى عضو

كل عضو يحتوي ثلاث مصفوفات جاهزة للتعبئة:

```js
{
  id: 'm1',
  name: 'محمد صالح السحيباني',
  role: 'عضو مؤسس',
  since: '٢٠٢٤',
  avatar: AVATAR_COLORS[0],

  quotes: [
    { id: 'q1', text: 'نص الاقتباس…', book: 'اسم الكتاب', date: '١٤ جمادى الأولى ١٤٤٦' }
  ],

  articles: [
    { id: 'a1', title: 'عنوان المقال', excerpt: 'مقتطف قصير…', date: '١٠ جمادى الأولى ١٤٤٦', link: 'رابط اختياري' }
  ],

  summaries: [
    { id: 's1', book: 'اسم الكتاب', author: 'المؤلف', text: 'نص الملخص…', date: '٣ جمادى الأولى ١٤٤٦' }
  ]
}
```

- أقسام الاقتباسات والمقالات والملخصات تظهر دائماً في صفحة العضو، مع توضيح عند خلو القسم من المحتوى.
- المحتوى الحالي عينة مؤقتة للتوضيح — استبدله بمحتوى الأعضاء الحقيقي.

### التخزين الجماعي (موصى به للكميات الكبيرة)

عند وجود ~٥٬٢٥٠ سجلاً (٧٠ عضواً × ٧٥ سجلاً) لا تُخزَّن البيانات داخل
`members.js`. بدلاً من ذلك:

- `data/content/index.json`: أعداد المحتوى لكل عضو (يُحمَّل في الصفحة الرئيسية).
- `data/content/<id>.json`: محتوى عضو واحد (يُحمَّل عند فتح صفحته فقط).

أداة الإدخال هي Google Sheet مع كود Apps Script جاهز في `tools/GoogleSheet_AppsScript.gs`
والخطوات في `tools/README.md`. الدالة «دفع إلى GitHub» تحدّث الملفات مباشرة،
فيتم النشر تلقائياً على Vercel. عامل الخدمة لا يخزّن ملفات `data/content/`
لضمان وصول التحديثات فوراً.

## التشغيل

افتح `index.html` مباشرة في المتصفح، أو من خلال خادم محلي:

```text
http://localhost:8765/jalees-members/index.html
```

> عامل الخدمة يحتاج `http/https` (لا يعمل على `file://`). وهو يفعّل العزل
> تلقائياً بعد أول زيارة، فلا تظهر صفحة الموقع الأساسي مطلقاً.

## النشر على Vercel (مهم)

المشروع المساند **مجلد مستقل** داخل المستودع. إذا كان جذر النشر في Vercel هو
جذر المستودع، فسيعرض Vercel `index.html` الخاص بالموقع الأساسي — وهذا هو سبب
تحويل الرابط إلى الموقع الأول.

**الأسهل (مطبّق بالفعل):** وُجد ملف `vercel.json` في **جذر المستودع** ويضبط
`outputDirectory` على `jalees-members`. يكفي دفعه إلى GitHub؛ سينشر Vercel
المجلس مباشرة على `https://jaleestool.vercel.app/` دون أي تعديل في إعداداته.
لإلغاء ذلك لاحقاً احذف هذا الملف — ملفات الموقع الأساسي لم تتغير.

**البديل من إعدادات Vercel** (إن لم ترد استخدام ملف الجذر):
`Project Settings` ← `General` ← `Root Directory` = `jalees-members`.
تنبيه: هذا الإعداد **ليس** داخل `Deployment Settings` الظاهر في لوحة Vercel.

الخطوات التالية مشتركة:

1. في Vercel افتح المشروع ← **Project Settings** ← **General**.
2. اضبط **Root Directory** على: `jalees-members`.
3. احفظ ثم أعد النشر (**Redeploy**).
4. بعدها يفتح الرابط `https://jaleestool.vercel.app/` مباشرة في «مجلس الأعضاء»
   (بدون `/jalees-members/`)، لأن هذا المجلد أصبح جذر النشر.
   إذا تُرك Root Directory على جذر المستودع، فالرابط الصحيح يكون
   `https://jaleestool.vercel.app/jalees-members/`.

بديل أنظف: انسخ محتوى مجلد `jalees-members` إلى مستودع GitHub مستقل،
واربط به مشروع Vercel جديد. بهذا ينفصل المشروعان تماماً على مستوى النطاق
والكاش وعامل الخدمة.

> إن فتحت الرابط بعد تغيير النشر وما زلت ترى الموقع الأساسي، فالسبب عامل خدمة
> قديم من النطاق نفسه. افتح الرابط ثم أغلقه، وامسح بيانات الموقع من المتصفح
> (Site data / Service workers) وأعد المحاولة. الكود فعّل تنظيفاً تلقائياً
> لعامل الخدمة القديم وكاشاته، لكن المتصفح قد يحتاج تحديثاً واحداً.

### الملفات التي تضمن الانفصال

- `sw.js`: نطاقه `/jalees-members/` فقط، ولا يعود للموقع الأساسي حتى دون اتصال.
- `script.js` → `isolateFromOriginalSite()`: يُلغي أي عامل خدمة آخر على النطاق
  ويحذف كاشات `jalees-*` الخاصة بالموقع الأساسي، دون تعديل ملفاته.
- `vercel.json`: يضبط ترويسة `Service-Worker-Allowed` ونطاق عامل الخدمة.
